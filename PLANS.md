# Post-0.9.1 Cleanup and Regression Repair

## Objective

Perform a conservative cleanup and bug-fixing pass after the 0.9.1 release, recovering any unintentionally lost 0.9.0 work while preserving intentional feature changes from both 0.9.0 and 0.9.1.

## Assumptions

- Release tags are local and authoritative for comparison.
- The current branch represents the post-0.9.1 cleanup target.
- README and generated MCP files may be partially generated by repository scripts, so generated sections should be regenerated through project commands where possible.
- Public MCP tool names, resource URIs, and runtime behavior should not change unless a verified bug requires it.

## Constraints

- Do not make commits.
- Do not broadly refactor or perform cosmetic churn.
- Restore only high-confidence accidental regressions.
- Preserve 0.9.1 additions while recovering 0.9.0 Claude Code support if it was lost.
- Treat any existing unrelated worktree changes as user-owned.

## Findings

- Package version is `0.9.1`.
- Relevant scripts present: `build`, `lint`, `test`, `coverage`, `test:matrix`, `mcp:generate`, `rag:rebuild`, `check`.
- No `typecheck` script is currently declared in `package.json`; build runs `tsc -p tsconfig.json`.
- Files present in `0.9.0` but absent in `0.9.1`/HEAD are `src/assemblyConverter.ts` and `src/basicConverter.ts`; these were intentional moves into `src/tools`, but the assembly target was misspelled as `assember.ts`.
- `.mcp.json` did not regress after `0.9.0`; README content did.
- `0.9.1` added batch/input/disassembler/symbol features and generated schema changes that should be preserved.
- Generated README/MCP artifacts are owned by `npm run build`, which runs `scripts/update-readme.ts` and `scripts/generate-mcp-interface.ts`.
- `mcp/server.json` was stale at version `0.9.0` before regeneration even though `package.json` is `0.9.1`; build regenerated it to `0.9.1`.
- Validation keeps line coverage above the repository threshold: `npm run coverage` reported 90.68% line coverage.
- `npm install` reports 2 audit vulnerabilities (1 moderate, 1 high); this appears unrelated to the cleanup and was not addressed because dependency upgrades are outside scope.

## Decisions

- Use `npm install` or `npm ci` after inspecting lockfile/package manager state.
- Use `npm run build` for TypeScript compilation plus README/MCP interface regeneration because it is the repository-owned build pipeline.
- Treat the README Claude Code removal as accidental because the first-class `.mcp.json` support remains and `0.9.1` did not replace it with another client setup.
- Treat `src/basicConverter.ts` to `src/tools/basicTokenizer.ts` as intentional and leave it unchanged.
- Treat `src/assemblyConverter.ts` moving into `src/tools` as intentional, but correct the typo from `assember.ts` to `assembler.ts`.
- Treat `data/assembly/assembly-spec.md` references to old converter paths as stale documentation introduced by the tool move; update them without changing resource names or public behavior.
- Treat `scripts/c64-cli.mjs` dynamic imports of removed `basicConverter` files as a small high-confidence regression from the 0.9.1 file move.
- Leave old names inside `doc/plans/**` untouched because those are historical planning records, not active runtime/docs surfaces.
- Leave the package dependency graph unchanged despite `npm audit` findings; this pass is release-regression repair, not dependency remediation.
- Treat `mcp/server.json` version correction as intentional generated artifact repair from the build pipeline.
