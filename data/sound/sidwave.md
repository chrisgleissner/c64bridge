# SIDWAVE Format Specification

This document defines **SIDWAVE**, a declarative format for describing structured C64 SID compositions.
SIDWAVE files are authored in YAML (or JSON) and compiled by the MCP server (`music_compile_and_play`) into a `.PRG` or `.SID` (PSID v2) binary with a built-in frame-based player.

Pipeline:

LLM → SIDWAVE (YAML) → MCP compiler → PRG or PSID → C64 / Ultimate / VICE playback

---

## File and Schema Conventions

- **Format name:** SIDWAVE
- **File suffix:** `.sidwave.yaml` (or `.sid.yaml` for brevity)
- **Version field:** `sidwave: 1.0`
- **Schema file:** `sidwave.schema.json`
- **Serialization:** YAML 1.2 or JSON

Unknown fields, unknown pattern names, invalid notes and out-of-range values are rejected with an error that names the path, for example `Invalid SIDWAVE at $.timeline[1].layers.v2: pattern "X" is not defined for voice 2 (known: B)`.

> YAML pitfall: inside a flow map, a bare `-` starts a list. Write silent layers as `v2: "-"`, not `v2: -`.

## Example

```yaml
# yaml-language-server: $schema=https://raw.githubusercontent.com/chrisgleissner/c64bridge/refs/heads/main/data/sound/sidwave.schema.json
sidwave: 1.0
title: "Echoes of Tomorrow"
author: "Generated by MCP"
tempo: 92
mode: PAL
global_fx:
  reverb_sim: { depth: 0.3, delay_frames: 3 }
  filter_env: { cutoff_base: 1800, sweep: -800, speed: 12 }

voices:
  - id: 1
    name: LeadPad
    waveform: sawtooth
    adsr: [4, 2, 10, 3]
    patterns:
      A:
        length: 16
        motif: "Cmin9 pad motif"
        transpositions: [0, 5, 7]
        fx:
          vibrato: { depth: 0.25, rate: 5, delay: 10 }
          filter_mod: { sweep: "+500 over 8 beats" }

  - id: 2
    name: ArpLayer
    waveform: pulse
    pulse_width: 0.3
    patterns:
      B:
        type: arpeggio
        notes: [C3, Eb3, G3, Bb3]
        frame_rate: 2
        fx:
          pwm_sweep: { speed: 1, depth: 0.2 }

  - id: 3
    name: Bass
    waveform: triangle
    patterns:
      C:
        groove: [C1, C1, C1, G0]
        fx:
          slide: { depth: 2, speed: 3 }

timeline:
  - section: "Intro"
    bars: 16
    layers: { v1: A, v2: "-", v3: C }
  - section: "Build"
    bars: 32
    layers: { v1: A↑, v2: B, v3: C }
  - section: "Drift"
    bars: 48
    layers: { v1: A↓, v2: B, v3: C }
  - section: "Fade"
    bars: 32
    layers: { v1: A–, v2: "-", v3: "-" }
```

## Song Fields

| Field | Meaning |
| --- | --- |
| `sidwave` | Format version, `1.0`. |
| `title`, `author` | Written to the PSID header (Latin-1, 32 characters). |
| `tempo` | Beats (quarter notes) per minute, 30–220. Default 100. |
| `mode` | `PAL` (985248 Hz clock, 50.12 frames/s) or `NTSC` (1022727 Hz clock, 59.83 frames/s). Default `PAL`. |
| `length_bars` | Optional song length. Shorter than the timeline truncates it; longer repeats the timeline from the start. Default: the sum of the timeline's bars. |
| `global_fx` | `reverb_sim` and `filter_env`, described below. |
| `voices` | One to three voices with ids 1–3. Voices that are not declared stay silent. |
| `timeline` | Sections played in order. The song loops forever after the last section. |

The legacy shape with a `song: { title, author, tempo, mode, length_bars, global_fx }` block next to `voices` and `timeline` is also accepted.

Time is 4/4: a bar has four beats. The player runs once per video frame of a real C64 (50.1245 Hz on PAL, 59.8262 Hz on NTSC). Every onset is placed on the nearest frame of its exact time (`beat × 60 / tempo × frame rate`), so long songs do not drift; individual notes may be one frame longer or shorter than the average.

## Voices

| Field | Meaning |
| --- | --- |
| `id` | SID voice 1, 2 or 3. |
| `name` | Label only. |
| `waveform` | `pulse`, `sawtooth` (`saw`), `triangle` (`tri`) or `noise`. Default `pulse`. |
| `pulse_width` | Pulse duty cycle: a fraction (0 < x ≤ 1, e.g. `0.3`) or a 12-bit value 1–4094. Default 2048 (50 %). |
| `adsr` | `[attack, decay, sustain, release]`, each 0–15 (SID register nibbles). Default `[2, 2, 10, 3]`. |
| `patterns` | Named patterns used by the timeline. |

## Patterns

Every pattern is a list of **entries**. Each entry lasts `length` beats (default 1; fractions allowed, e.g. `0.25` for sixteenth notes). The pattern repeats until its section ends; a note that would run past the section end is cut there.

- **groove** — `groove: [C2, "-", C2, "~", G1]`: one note per entry. `-` (or `.`) is a rest, `~` ties the entry to the previous note (no retrigger).
- **arpeggio** — `type: arpeggio`, `notes: [...]`. Without `frame_rate`, the notes are played one per entry (a broken chord). With `frame_rate: N`, all notes form one entry that sounds as a fast chord arpeggio, switching to the next chord tone every N frames (`frame_rate: 1` = one tone per frame, about 50 per second on PAL); each entry retriggers the chord.
- **motif** — `motif: "..."` with tokens separated by spaces or commas:
  - note names (`C4`, `Eb3`, `F#2`),
  - integers: semitones above `root` (default `C3`), e.g. `"0 4 7 12"`,
  - chord symbols, expanded to their chord tones in the octave of `root`: `C`, `Cm`/`Cmin`, `Cdim`, `Caug`, `Csus2`, `Csus4`, `C6`, `Cm6`, `C7`, `Cmaj7`, `Cm7`, `Cdim7`, `Cm7b5`, `C9`, `Cmaj9`, `Cm9`/`Cmin9`, `Cadd9`,
  - `-` rests and `~` ties.
  Words that are not notes or chord symbols (such as `pad` or `motif`) are ignored. `"Cmin9 pad motif"` therefore plays C3, Eb3, G3, Bb3, D4, one per entry.

`transpositions: [0, 5, 7]` transposes successive repetitions of the pattern within a section by the given semitones, cycling; the cycle restarts at each section.

Notes range from C0 to B7. At the PAL clock B7 exceeds the SID's 16-bit frequency register, so the highest PAL note is A#7. Notes that leave the range after transposition are rejected.

### Pattern effects (`fx`)

| Effect | Fields | Behaviour |
| --- | --- | --- |
| `vibrato` | `depth` (semitones, 0.03–6), `rate` (Hz, 0.2–25), `delay` (frames, optional) | Triangle pitch modulation of ±`depth` semitones around the note, starting `delay` frames after the note. |
| `pwm_sweep` | `depth` (fraction ≤ 1 or 12-bit units), `speed` (cycles per second) | Pulse width moves linearly between `pulse_width − depth` and `pulse_width + depth`, restarting at the base on each note. Pulse waveform only. |
| `slide` | `depth` (semitones, ±24, non-zero), `speed` (frames) | Each note starts `depth` semitones below the target (above when negative) and glides to it in `speed` frames. |
| `filter_mod` | `sweep: "+500 over 8 steps"` (units: `steps`, `beats`, `bars`, `frames`; a step is one entry), or `{ sweep: 500, beats: 8 }` | Routes the voice through the filter while the pattern plays. At each repetition of the pattern the cutoff offset restarts at 0 and ramps to `sweep` (cutoff units, −2047..2047) over the given time, then holds. The offset is removed when the section ends. |

## Timeline

Each section has `bars` (whole number ≥ 1), an optional `section` name, and `layers` mapping `v1`/`v2`/`v3` to a pattern reference:

- `"-"`, `.`, `rest` or an omitted layer: the voice is silent.
- `A`: play pattern `A` of that voice.
- Modifiers after the name: `↑` (or `^`) one octave up, `↓` one octave down, `+N` / `-N` N semitones (e.g. `A+5`), and a trailing `–`, `—` or `-` fades the voice out over the section.

Fading lowers the voice's sustain level linearly to 0 across the section. When every sounding voice of a section fades, the master volume also fades to 0 and returns to full volume when the section ends.

## Global effects (`global_fx`)

| Effect | Fields | Behaviour |
| --- | --- | --- |
| `filter_env` | `cutoff_base` (0–2047), `sweep` (±2047), `speed` (beats per one-way sweep), `resonance` (0–15, default 8), `type` (`lowpass` default, `bandpass`, `highpass`), `voices` (default all) | Enables the SID filter for the listed voices. The cutoff moves back and forth between `cutoff_base` and `cutoff_base + sweep`, each direction taking `speed` beats. Without `sweep`/`speed` the cutoff stays at `cutoff_base`. `filter_mod` offsets are added on top. |
| `reverb_sim` | `depth` (0 < x ≤ 1), `delay_frames` (1–50) | In sections that leave a voice free, the lowest free voice echoes the lowest sounding voice `delay_frames` later, with its sustain level scaled by `depth`. The SID has no per-voice volume, so the echo's attack peak is as loud as the original; only the sustained part is quieter. Sections that use all three voices have no echo. |

Without `filter_env`, a `filter_mod` uses a low-pass filter with cutoff 1024 and resonance 8 as its base. The SID has a single filter, so all routed voices share it; when several patterns with `filter_mod` start at once, the most recent start sets the ramp.

## Player

The compiler arranges the timeline into per-voice note events and encodes them as compact command streams (note, instrument, wait, gate-off, hard restart, sustain, volume, filter ramp, loop). A 6502 player reads these streams once per video frame and computes per-frame effects itself.

- **Hard restart:** two frames before every new note the voice's gate is released and its ADSR is set to zero, so each note starts a fresh envelope (this avoids the SID's ADSR delay bug). A note therefore sounds with the gate on until two frames before the next note; it must last at least 2 frames, which limits very short entries at fast tempos.
- **Gate:** a rest releases the gate at its start, so the note decays with its release rate.
- **Instruments:** each voice/pattern/effect combination becomes an instrument with its own ADSR, waveform, pulse settings, vibrato, arpeggio table, slide and filter routing (up to 63).
- **Memory:** the program loads at $0801 and must end below $D000 (about 50 KB). Very long, dense songs are rejected with an error rather than truncated.
- **CPU time:** typical songs take 20–55 raster lines per frame (about 1,400–3,400 cycles). The worst case, all three voices starting notes with vibrato, slide, arpeggio, pulse sweep and filter ramp in the same frame, takes about 7,800 cycles (124 raster lines, 40 % of a PAL frame), mostly for the multiplications that scale vibrato and slide to each note's pitch.

### Output formats

- **PSID (`output: sid`):** PSID v2 with init at $0810, play at $0813, vertical-blank timing, and the PAL or NTSC clock flag from `mode`. The SID model is left unspecified.
- **PRG (`output: prg`):** `10 SYS2061`. The program detects whether the machine is PAL or NTSC, programs the CIA timer for the song's frame rate on that clock, installs an IRQ handler, and returns to BASIC while the music plays. Pitch and tempo are therefore correct on either machine type.

### Not supported

Time signatures other than 4/4, per-note velocity, portamento between consecutive notes (the `slide` effect is a slide into each note), multiple subtunes, multispeed (more than one player call per frame), and combined waveforms.

## Authoring and Validation

- Validation uses JSON Schema (`sidwave.schema.json`); the compiler applies the same rules and additionally checks note ranges after transposition and minimum note durations.

```json
{
  "yaml.schemas": {
    "https://raw.githubusercontent.com/chrisgleissner/c64bridge/refs/heads/main/data/sound/sidwave.schema.json": "*.sidwave.yaml"
  }
}
```
