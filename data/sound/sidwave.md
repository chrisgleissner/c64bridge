# SIDWAVE Format Specification

This document defines **SIDWAVE**, a declarative format for describing structured C64 SID compositions.
SIDWAVE files are authored in YAML (or JSON) and compiled by the MCP server (`music_compile_and_play`) into a `.PRG` or `.SID` binary with a built-in frame-based player.

Pipeline:

LLM → SIDWAVE (YAML) → MCP compiler → PRG or PSID → C64 / Ultimate / VICE playback

---

## File and Schema Conventions

- **Format name:** SIDWAVE
- **File suffix:** `.sidwave.yaml` (or `.sid.yaml` for brevity)
- **Version field:** `sidwave: 1.0`, `sidwave: 1.1`, or `sidwave: 1.2`
- **Schema file:** `sidwave.schema.json`
- **Serialization:** YAML 1.2 or JSON

Unknown fields, unknown pattern names, invalid notes and out-of-range values are rejected with an error that names the path, for example `Invalid SIDWAVE at $.timeline[1].layers.v2: pattern "X" is not defined for voice 2 (known: B)`.

> YAML pitfall: inside a flow map, a bare `-` starts a list. Write silent layers as `v2: "-"`, not `v2: -`.

## Example

```yaml
# yaml-language-server: $schema=https://raw.githubusercontent.com/chrisgleissner/c64bridge/refs/heads/main/data/sound/sidwave.schema.json
sidwave: 1.0
title: "Echoes of Tomorrow"
author: "Generated by MCP"
tempo: 92
mode: PAL
global_fx:
  reverb_sim: { depth: 0.3, delay_frames: 3 }
  filter_env: { cutoff_base: 1800, sweep: -800, speed: 12 }

voices:
  - id: 1
    name: LeadPad
    waveform: sawtooth
    adsr: [4, 2, 10, 3]
    patterns:
      A:
        length: 16
        motif: "Cmin9 pad motif"
        transpositions: [0, 5, 7]
        fx:
          vibrato: { depth: 0.25, rate: 5, delay: 10 }
          filter_mod: { sweep: "+500 over 8 beats" }

  - id: 2
    name: ArpLayer
    waveform: pulse
    pulse_width: 0.3
    patterns:
      B:
        type: arpeggio
        notes: [C3, Eb3, G3, Bb3]
        frame_rate: 2
        fx:
          pwm_sweep: { speed: 1, depth: 0.2 }

  - id: 3
    name: Bass
    waveform: triangle
    patterns:
      C:
        groove: [C1, C1, C1, G0]
        fx:
          slide: { depth: 2, speed: 3 }

timeline:
  - section: "Intro"
    bars: 16
    layers: { v1: A, v2: "-", v3: C }
  - section: "Build"
    bars: 32
    layers: { v1: A↑, v2: B, v3: C }
  - section: "Drift"
    bars: 48
    layers: { v1: A↓, v2: B, v3: C }
  - section: "Fade"
    bars: 32
    layers: { v1: A–, v2: "-", v3: "-" }
```

## Song Fields

| Field | Meaning |
| --- | --- |
| `sidwave` | Format version, `1.0` (legacy), `1.1`, or `1.2`. |
| `instruments` | Optional named instrument map. Voices may select an instrument; `lib:name` selects a built-in recipe. |
| `speed` | Player calls per frame, from 1 to 4. |
| `title`, `author` | Written to the PSID header (Latin-1, 32 characters). |
| `meter` | Quarter notes per bar. Defaults to 4. In 1.2 use `meter: 3` for 3/4. |
| `tempo` | Beats (quarter notes) per minute, 30–220. Default 100. |
| `mode` | `PAL` (985248 Hz clock, 50.12 frames/s) or `NTSC` (1022727 Hz clock, 59.83 frames/s). Default `PAL`. |
| `length_bars` | Optional song length. Shorter than the timeline truncates it; longer repeats the timeline from the start. Default: the sum of the timeline's bars. |
| `global_fx` | `reverb_sim` and `filter_env`, described below. |
| `samples` | Optional CIA2 volume samples and their trigger calls (1.2 PRG). |
| `sids` | Optional SID map or layout. Defaults to one SID at `$D400`. |
| `cpu` | Optional `turbo` for standalone PRG playback on Ultimate hardware. |
| `voices` | One to 30 voices, up to three per configured SID. Undeclared channels stay silent. |
| `timeline` | Sections played in order. The song loops forever after the last section. |

### Instrument wavetables

An instrument may define `wavetable` as ordered control and pitch steps. Each step runs for `frames` player calls (default 1); the last step holds unless the instrument sets `loop` to a zero-based step index. Omitted `wave` retains the instrument waveform. `gate` defaults to on. `ring`, `sync`, and `test` set the SID control register bits for that step. A step `note` of `+N` or `-N` offsets the played note by semitones; a note name such as `C5` fixes the pitch regardless of the played note. Pitch effects such as vibrato, slide, and arpeggio are bypassed while a step has a note override. A new attack starts the table at its first step. A legato note continues the running table.

```yaml
instruments:
  kick:
    wavetable:
      - { wave: noise, note: C6 }
      - { wave: pulse, note: C3 }
      - { wave: pulse, note: A2 }
      - { wave: pulse, note: F2 }
  octave:
    loop: 0
    wavetable:
      - { note: '+0' }
      - { note: '+12' }
```

### Instrument pulse and filter tables

Both tables restart on each note start and advance once per player call, including at
`speed` greater than 1. A table can be a list of steps or a mapping with `steps`
and its own zero-based `loop` index. For lists, an instrument-level `loop`
applies to each list on that instrument. Without a loop, the last value holds
after the final step finishes, including when the last step was an `add`. The
compiled player supports up to 255 pulse steps and 255 filter steps across its
instrument variants.

`pulsetable` supplies the voice's pulse width via `$D402 + 7v` and
`$D403 + 7v` (`v` is 0–2). A `set` takes a fraction in `(0, 1]` or an
integer from 1 to 4094. Values up to and including 1 are interpreted as fractions,
scaled by 4095, rounded, and clamped to 1–4094. An `add` applies a signed
delta from −2048 to 2047 on each of its `frames` calls (1–255), clamping the
result to 1–4094. A `set` lasts one call by default and can also specify
`frames`. The table takes priority over `pwm_sweep`. If the first step is an
`add`, it starts from the note's `pulse_width` (default 2048).

`filtertable` sets the cutoff to an integer in 0–2047 with `cutoff`, or
changes it on every call with an `add` delta from −2048 to 2047, clamped to
0–2047. Each step has `frames` in 1–255 (default 1). Optional `resonance`
(0–15) and `type` carry forward when omitted. A note starts with cutoff 0,
resonance 8, and `lowpass` before its first step runs. The filter types are
`lowpass`, `bandpass`, `highpass`, `lowpass+highpass`, `bandpass+highpass`,
and `all`. The player puts cutoff bits 0–2 in `$D415` and bits 3–10 in
`$D416`, resonance and routing in `$D417`, and type in `$D418` while
preserving the current master volume.

The SID has one shared filter. Every playing note with a filter table routes its voice
through it, and the most recently started of those notes controls the settings.
If several start on the same call, the highest numbered voice wins. Each active
table advances in the background, so the next most recent note can take over
at its current step when the owner releases or enters hard restart. While a
table owns the filter, global routing and the `filter_env` and `filter_mod`
sweeps are suspended. The sweeps resume from their paused positions when
ownership ends. Scheduled ramp changes and song-loop resets still take effect
at their usual times.

```yaml
instruments:
  sweep_bass:
    waveform: pulse
    pulsetable:
      loop: 0
      steps:
        - { set: 0.35 }
        - { add: 23, frames: 8 }
        - { add: -23, frames: 8 }
    filtertable:
      - { cutoff: 1300, resonance: 10, type: lowpass }
      - { add: -40, frames: 12 }
```

The emulator budget fixture runs two song loops with three wavetable and pulse
table voices and one filter table. Its highest measured play call takes **3088
6502 cycles**, including indexed reads and branches that cross pages. The player
and its data grow from **3975 to 4577 bytes** (+602) versus the same fixture
with wavetables alone, excluding the PRG load address and song streams.

The three-voice example below peaks at **3903 cycles per player call** in the
emulator. Its player and data use **4944 bytes**, up from **4844 bytes** with
portamento and legato removed from the same score. Song streams are counted
separately.

The legacy shape with a `song: { title, author, tempo, mode, length_bars, global_fx }` block next to `voices` and `timeline` is also accepted.

A bar lasts four beats by default. A score with `meter: 3` has three beats to a bar, including durations specified in bars. The player runs `speed` times per video frame (50.1245 Hz on PAL, 59.8262 Hz on NTSC). Each onset is rounded to the nearest player call using `beat × 60 / tempo × frame rate × speed`. Individual notes can differ by a call as a result of rounding.

## Voices

| Field | Meaning |
| --- | --- |
| `id` | SID voice 1, 2 or 3. |
| `name` | Label only. |
| `waveform` | `pulse`, `sawtooth` (`saw`), `triangle` (`tri`) or `noise`. Default `pulse`. |
| `pulse_width` | Pulse duty cycle: a fraction (0 < x ≤ 1, e.g. `0.3`) or a 12-bit value 1–4094. Default 2048 (50 %). |
| `adsr` | `[attack, decay, sustain, release]`, each 0–15 (SID register nibbles). Default `[2, 2, 10, 3]`. |
| `instrument` | Default named instrument or `lib:<name>` recipe. |
| `patterns` | Named patterns used by the timeline. |

## Patterns

Every pattern is a list of **entries**. Each entry lasts `length` beats (default 1; fractions allowed, e.g. `0.25` for sixteenth notes). The pattern repeats until its section ends; a note that would run past the section end is cut there.

- **groove** — `groove: [C2, "-", C2, "~", G1]`: one note per entry. `-` (or `.`) is a rest, `~` ties the entry to the previous note (no retrigger). A tie holds whatever note is sounding right before it, also across a section boundary (a section that starts with `~` continues the last note of the previous section). After a rest, or at the very start of the song, a tie is a rest.
- **per-note options** — Write `C3@bass` to choose an instrument or `{ note: C3, inst: bass, len: 0.25, legato: true, portamento: 4 }` to set articulation and override the note duration in beats.
- **drums** — `drums: { kit: { k: lib:kick, s: lib:snare, h: lib:hat }, steps: "k.h.s.h." }` is an alternative to `groove`. Each character occupies one entry of `length` beats. A period is a rest and each letter plays the mapped instrument at C3. The library drums use absolute pitches in their wavetables, so score transposition leaves their pitches alone.
- **arpeggio** — `type: arpeggio`, `notes: [...]`. Without `frame_rate`, the notes are played one per entry (a broken chord). With `frame_rate: N`, all notes form one entry that sounds as a fast chord arpeggio, switching to the next chord tone every N frames (`frame_rate: 1` = one tone per frame, about 50 per second on PAL); each entry retriggers the chord.
- **motif** — `motif: "..."` with tokens separated by spaces or commas:
  - note names (`C4`, `Eb3`, `F#2`),
  - integers: semitones above `root` (default `C3`), e.g. `"0 4 7 12"`,
  - chord symbols, expanded to their chord tones in the octave of `root`: `C`, `Cm`/`Cmin`, `Cdim`, `Caug`, `Csus2`, `Csus4`, `C6`, `Cm6`, `C7`, `Cmaj7`, `Cm7`, `Cdim7`, `Cm7b5`, `C9`, `Cmaj9`, `Cm9`/`Cmin9`, `Cadd9`,
  - `-` rests and `~` ties.
  Words that are not notes or chord symbols (such as `pad` or `motif`) are ignored. `"Cmin9 pad motif"` therefore plays C3, Eb3, G3, Bb3, D4, one per entry.

`transpositions: [0, 5, 7]` transposes successive repetitions of the pattern within a section by the given semitones, cycling; the cycle restarts at each section.

Notes range from C0 to B7. At the PAL clock B7 exceeds the SID's 16-bit frequency register, so the highest PAL note is A#7. Notes that leave the range after transposition are rejected.

### Pattern effects (`fx`)

| Effect | Fields | Behaviour |
| --- | --- | --- |
| `vibrato` | `depth` (semitones, 0.03–6), `rate` (Hz, 0.2–12), `delay` (frames, optional) | Triangle pitch modulation of ±`depth` semitones around the note (the upward and downward swings are computed separately, so both reach `depth` to within the SID's frequency resolution, about 6 cents at C0 and 3 cents at C1 on PAL), starting `delay` frames after the note. The upward swing must stay within the SID's highest frequency: on PAL a vibrato on A#7 can be at most 0.54 semitones deep, on NTSC B7 at most 0.19; deeper vibratos on such notes (including the highest note of a chord arpeggio) are rejected. The player samples the vibrato once per frame, so rates are limited to 12 Hz (about a quarter of the frame rate); faster rates would alias or cancel out. |
| `pwm_sweep` | `depth` (fraction ≤ 1 or 12-bit units), `speed` (cycles per second) | Pulse width moves linearly between `pulse_width − depth` and `pulse_width + depth`, restarting at the base on each note. Pulse waveform only. |
| `slide` | `depth` (semitones, ±24, non-zero), `speed` (frames, 1–255) | Each note starts `depth` semitones below the target (above when negative) and glides to it linearly in frequency, arriving after `speed` frames. The start note must itself be playable (C0..A#7 on PAL, C0..B7 on NTSC); otherwise the document is rejected. |
| `filter_mod` | `sweep: "+500 over 8 steps"` (units: `steps`, `beats`, `bars`, `frames`; a step is one entry), or `{ sweep: 500, beats: 8 }` | Routes the voice through the filter while the pattern plays. At each repetition of the pattern the cutoff offset restarts at 0 and ramps to `sweep` (cutoff units, −2047..2047) over the given time, then holds. The resulting cutoff is clamped to 0..2047. The offset is removed when the section ends. |

## Timeline

Each section has `bars` (whole number ≥ 1), an optional `section` name, and `layers` mapping `v1`/`v2`/`v3` to a pattern reference:

- `"-"`, `.`, `rest` or an omitted layer: the voice is silent.
- `A`: play pattern `A` of that voice.
- Modifiers after the name: `↑` (or `^`) one octave up, `↓` one octave down, `+N` / `-N` N semitones (e.g. `A+5`), and a trailing `–`, `—` or `-` fades the voice out over the section.

Fading lowers the voice's sustain level linearly to 0 across the section. When every sounding voice of a section fades, the master volume also fades to 0 and returns to full volume when the section ends.

## Global effects (`global_fx`)

| Effect | Fields | Behaviour |
| --- | --- | --- |
| `filter_env` | `cutoff_base` (0–2047), `sweep` (±2047), `speed` (beats per one-way sweep), `resonance` (0–15, default 8), `type` (`lowpass` default, `bandpass`, `highpass`), `voices` (default all) | Enables the SID filter for the listed voices. The cutoff moves back and forth between `cutoff_base` and `cutoff_base + sweep`, each direction taking `speed` beats. Without `sweep`/`speed` the cutoff stays at `cutoff_base`. The sweep restarts from `cutoff_base` each time the song loops, so every pass sounds the same. `filter_mod` offsets are added on top. |
| `reverb_sim` | `depth` (0 < x ≤ 1), `delay_frames` (1–50) | In sections that leave a voice free, the lowest free voice echoes the lowest sounding voice `delay_frames` later, with its sustain level scaled by `depth`. The SID has no per-voice volume, so the echo's attack peak is as loud as the original; only the sustained part is quieter. Sections that use all three voices have no echo. |

Without `filter_env`, a `filter_mod` uses a low-pass filter with cutoff 1024 and resonance 8 as its base. The SID has a single filter, so all routed voices share it; when several patterns with `filter_mod` start at once, the most recent start sets the ramp.

## Portamento and legato

Set either field on a named instrument or on a groove note object. Entry values take precedence over the instrument defaults.

- `portamento: N` starts from the preceding note's pitch on the same voice, including after a rest. It reaches the new target after **N player calls**, interpolating the SID frequency linearly. The range is 0–255. Zero disables the glide. The first note of each loop starts normally. A glide replaces the instrument's ordinary slide for that note. Wavetable rows that set a pitch take precedence while those rows are active.
- `legato: true` changes the pitch of a contiguous note while preserving the active instrument, gate, ADSR and table positions. If the entry names another instrument, that instrument's articulation settings still apply. Use a normal attack to switch the sounding instrument. After a rest or at the start of the loop, the player makes a normal attack. An explicit `false` restores hard restart when the instrument defaults to legato.

## Generated pieces

`c64_sound` with `op: generate` plays a seeded eight-bar piece once and returns
a short summary and the resource URI for a bundled example in the chosen style.
Set `includeScore: true` to receive the generated SIDWAVE source and lead timeline.
Like `play_preset`, it loads the song as a PRG with its own player,
which replaces the program in memory. The styles are `chiptune` (130 BPM, speed 2), `ambient`
(80 BPM) and `funk` (105 BPM). Use `seed` to reproduce the harmony and melody.

`root` sets the tonic and lead register. An explicit `pattern` repeats semitone
offsets relative to that root. `steps` sets the number of lead notes and
`tempoMs` sets their spacing with `preset: classic`. The `expression` preset
uses varied phrasing and retains its 250, 180, 180 and 400 ms timing cycle when
you customize the lead length, pattern or spacing. The accompaniment then runs
to the end of the final bar. `waveform` overrides the lead sound, and `system`
sets the score timing to PAL or NTSC. By default, timing follows the machine.

## Built-in instruments

Use these names as voice defaults, groove note instruments, or drum kit entries. The recipes use techniques described in [SID programming best practices](sid-programming-best-practices.md) and the [SID specification](sid-spec.md).

| Name | Sound |
| --- | --- |
| `lib:kick` | One noise transient followed by descending pulse and triangle pitches. |
| `lib:snare` | A longer noise burst with a falling noise pitch and a short pitched body. |
| `lib:hat` | A bright noise tick that drops in pitch and releases quickly. |
| `lib:bass_pluck` | An octave pulse transient over a decaying triangle bass. |
| `lib:filter_bass` | A saw bass with a resonant low-pass filter sweep on each attack. |
| `lib:lead_pwm` | A pulse lead with a looping pulse width sweep. |
| `lib:chip_arp_major` | A repeating root, major third, fifth and octave on one voice. |
| `lib:chip_arp_minor` | A repeating root, minor third, fifth and octave on one voice. |
| `lib:bell_ring` | A ring modulated triangle with a bright octave attack. |
| `lib:sync_lead` | A hard synced saw with a short octave transient. |
| `lib:pad_slow` | A slow triangle envelope with a cycling low-pass filter. |

## SIDWAVE 1.1 authoring techniques

Share a voice between wavetable drums and filtered bass. Cycle chord tones quickly on a second voice and give the third voice a PWM lead with delayed vibrato and legato glides. Use hard restart for a fresh attack. Vary phrases with octave jumps or add a delayed copy to an otherwise free voice. The SID has one shared filter. The most recent active filter table controls its settings. Voice 1 takes its ring or sync source from voice 3, voice 2 from voice 1, and voice 3 from voice 2. Choose notes for that source voice when writing a ring or sync accent. Combined waveforms can be quieter and sound different on a 6581 and an 8580.

```yaml
sidwave: 1.1
title: Night Signals
tempo: 132
mode: PAL
speed: 2
instruments:
  ribbon:
    waveform: pulse
    adsr: [1, 4, 10, 3]
    portamento: 5
    pulsetable:
      steps: [{ set: 0.25 }, { add: 28, frames: 15 }, { add: -28, frames: 15 }]
      loop: 1
    vibrato: { depth: 0.35, rate: 5, delay: 8 }
voices:
  - id: 1
    instrument: lib:filter_bass
    patterns:
      line: { length: 0.5, groove: [C2, C2@lib:hat, G1, C2@lib:snare, C2, Bb1, C2@lib:kick, "-"] }
      break: { length: 0.5, drums: { kit: { k: lib:kick, s: lib:snare, h: lib:hat }, steps: "k.h.s.h." } }
  - id: 2
    instrument: lib:chip_arp_major
    patterns:
      chord: { groove: [C4, C4, G3, Bb3@lib:chip_arp_minor] }
  - id: 3
    instrument: ribbon
    patterns:
      lead:
        length: 0.5
        groove:
          - C5
          - { note: G4, legato: true }
          - E5
          - { note: D5, legato: true, portamento: 3 }
          - C5@lib:bell_ring
          - "-"
          - G4
          - { note: C5, legato: true }
timeline:
  - { section: Theme, bars: 2, layers: { v1: line, v2: chord, v3: lead } }
  - { section: Break, bars: 1, layers: { v1: break, v2: chord+12, v3: lead } }
```

## Player

The compiler arranges the timeline into per-voice note events and encodes them as compact command streams (note, instrument, wait, gate-off, hard restart, portamento, legato, sustain, volume, filter ramp, loop). A 6502 player reads these streams on each call and computes per-frame effects itself.

- **Hard restart:** two calls before a new attack the player clears the voice's gate bit and writes 0 to its attack/decay and sustain/release registers. Release 0 takes the envelope from any level to zero in 6 ms (Mapping the Commodore 64, `$D406`), well inside the 2 calls at normal speed (40 ms PAL, 33 ms NTSC). Rate 0 also sets the shortest envelope rate period (9 cycles), so at the next gate-on the SID's rate counter is below the new attack period. A rate counter above the new period would count on to 32768 and wrap before the envelope moves, delaying the attack by up to 32768 cycles (33 ms at the PAL clock) (the ADSR delay bug, reSID `envelope.h`, measured by Dag Lem by sampling ENV3 on a MOS SID). A note therefore sounds with the gate on until two calls before the next attack, so every note needs at least 3 calls (one sounding frame plus the hard restart). Entries shorter than 3 calls are rejected, which limits very short entries at fast tempos (for example 1/16 notes are fine at 220 BPM, 1/32 notes are not). A note that is cut to fewer than 3 calls by the end of a section is dropped.
- **Gate:** a rest releases the gate at its start, so the note decays with its release rate.
- **Instruments:** each voice/pattern/effect combination becomes an instrument with its own ADSR, waveform, pulse settings, vibrato, arpeggio table, slide and filter routing (up to 63).
- **Memory:** the program loads at $0801 and must end below $D000 (about 50 KB). Very long, dense songs are rejected with a validation error rather than truncated. The player uses zero-page bytes $FB/$FC and restores them after every call.
- **CPU time:** typical songs take 20–65 raster lines per frame (about 1,300–4,100 cycles at 63 cycles per PAL line). The worst case, all three voices starting notes with vibrato, slide, arpeggio, pulse sweep and filter ramp in the same frame, takes about 9,800 cycles (155 raster lines, half a PAL frame), mostly for the arithmetic that scales vibrato and slide to each note's pitch (an 8×8 multiply from a 1 KB table of squares).

### Output formats

- **PSID (`output: sid`):** v2 for one SID, v3 for two and v4 for three. The map must include the primary SID at `$D400`. The byte at `$7A` encodes the second SID base and `$7B` encodes the third. For example, `$42` means `$D420`. The payload begins at `$7C` in all three versions. An optional `model` sets that SID's model flag. This follows the HVSC specification. [SID_file_format.txt](https://hvsc.c64.org/download/C64Music/DOCUMENTS/SID_file_format.txt)
  - Init is at `$0810` and play is at `$0813`. The header clock flag follows `mode`. Speed 1 uses vertical blank timing. Higher speeds set the first song's CIA timing bit and write the CIA timer latch in init.
- **PRG (`output: prg`):** `10 SYS2061`. The program detects whether the machine is PAL or NTSC, programs CIA 1 timer A for the song’s play rate on that clock, installs an IRQ handler, and returns to BASIC while the music plays. Pitch and tempo are therefore correct on either machine type.
  - Before returning, it moves the start of BASIC and the variable area behind the player (like `NEW` with a raised start of BASIC), so direct-mode commands, variables and new program lines work without touching the player. The compile result reports `basicFreeBytes`. A song whose PRG ends at or above $A000 leaves no BASIC memory: BASIC commands that need memory then fail with `?OUT OF MEMORY` while the music keeps playing, and the compile result carries a warning.
  - The KERNAL IRQ (keyboard scan, cursor blink, jiffy clock) runs at the song’s play rate. At speed 1, `TI`/`TI$` runs about 16.5% slow for a PAL song and 0.3% slow for NTSC. Higher speeds also increase the KERNAL IRQ rate.

## Multiple SIDs (1.2)

List the SID windows in playback order, or use a layout from [Owner configurations](../ultimate/multisid.md#owner-configurations-and-settings). Use distinct IDs and distinct addresses from `$D400` through `$D7E0` in `$20` increments. The compiler refuses `$DE00–$DFFF`. Use PRG for a map with more than three SIDs. Before playing a multi-SID PRG, configure the device to decode those same windows.

| Layout | SID bases in voice order |
|---|---|
| `ultisid8` | `$D400 $D480 $D500 $D580 $D420 $D4A0 $D520 $D5A0` |
| `ultisid8+socket1` | The eight bases above, then `$D440` |
| `ultisid8+sockets` | The eight bases above, then `$D440 $D460` |

The layouts assign IDs `sid1` through `sid10` in list order. Use `overrides: { sid1: { volume: 9, pan: "Left 5" } }` inside a layout to set mixer preferences without changing its addresses. Numeric voice IDs address groups of three, so `v4` is channel 1 of the second SID and `v30` is channel 3 of the tenth. Set `sid` and `channel` instead to select a named chip and a channel. The voice ID defaults to its physical slot (1–30). You can supply an explicit `id` to label that voice in the timeline. Ring and sync use the preceding oscillator on the same chip, with channel 3 as the source for channel 1.

```yaml
sidwave: 1.2
title: Two windows
tempo: 120
mode: PAL
sids:
  - { id: bass, address: "$D400", model: "8580", volume: 12 }
  - id: lead
    address: "$D420"
    volume: 8
    filter:
      filter_env: { cutoff_base: 800, sweep: 500, speed: 4, voices: [2] }
      filter_mod: { sweep: 100, beats: 2 }
voices:
  - { id: 1, waveform: sawtooth, patterns: { A: { groove: [C3, G2] } } }
  - { sid: lead, channel: 2, waveform: triangle, patterns: { A: { groove: [E4, G4] } } }
timeline:
  - { bars: 1, layers: { v1: A, v5: A } }
```

Each SID's volume defaults to 15. Its `filter.filter_env.voices` uses local channels 1–3. A pattern's `filter_mod` affects the SID that plays the pattern. A SID's optional `filter.filter_mod` starts its ramp at the beginning of each pass. Its `steps` unit uses one beat per step. The most recent active filter table owns cutoff, mode and resonance for its own SID. Filter tables on other SIDs run independently. Top-level `global_fx.filter_env` applies to the first SID unless its own `filter_env` overrides it.

The compiler warns if the sum of peak sawtooth sustain scaled by each SID's volume exceeds 10. The estimate assumes all SIDs could share a pan side because the score does not describe the hardware mixer. Keep the actual sum of `(volume / 15) × (sustain / 15)` per side at or below 10. [Ultimate multi-SID level measurements](../ultimate/multisid.md)

The compiler reports `worstCaseCyclesPerCall` and refuses a 1.2 score above the 1 MHz budget for its selected video standard unless it declares `cpu: turbo`. The error gives the minimum CPU speed. Higher values of `speed` leave fewer cycles per player call. Song code and data must fit below `$D000`.

For a turbo PRG, select `U64 Turbo Registers` on an Ultimate 64 or `C64U Turbo Registers` on a C64 Ultimate. The PRG requests top speed through `$D031` and counts loop iterations across a raster line. Playback begins when it measures more than about 1.5 MHz or reaches the 4.25-second cap. A reset can trigger the full startup hold, while a reset-free launch can begin on the first check. If the registers are unavailable and the score exceeds the stock budget, the PRG returns to BASIC without installing its IRQ. [Ultimate hardware turbo timing](../ultimate/hardware.md)

The SIDWAVE 1.2 player clears each SID at init, then raises its master volume
from zero by one step per video frame (about 20 ms on PAL or 17 ms on NTSC),
even with a multispeed score. At the end of a play-once score it releases
the voice gates and lowers the master volume at the same rate before stopping.
The volume changes preserve each SID's filter mode bits. Active digi samples
temporarily write their raw four-bit values to the volume register on their SID.

### Playback setup

On Ultimate backends, `compile_play`, `pipeline`, `play_preset`, and `generate`
start a SIDWAVE PRG without a reset when BASIC is idle at `READY.` or the
SIDWAVE player owns the IRQ and the keyboard queue is idle. The server detaches
the previous player, clears the SID registers, DMA-writes the PRG body, and
queues a BASIC `SYS` command. Other machine states use the normal PRG runner.

The capture harness at `scripts/sidwave-hil.mjs` uses the same launcher.
It starts recording before launching the score so the capture includes startup.

These operations accept `configure: true`. On supported Ultimate firmware,
the server snapshots the SID addressing, sockets, mixer, and UltiSID stores in
memory. It clears the old SID windows before changing the map and clears the
new windows afterward. It restores the changed settings when playback stops,
is replaced, the machine resets, or the active backend switches. A dry run
leaves the device alone.

The three `ultisid8` layouts disable mirroring and split both UltiSIDs with `1/4 (A7,A8)`. The bases are `$D400` and `$D420`. The layouts map and enable the required sockets at `$D440` and `$D460`. For explicit maps, the server can configure subsets of those windows and maps using up to four unsplit decoders. Other maps require manual setup. [Owner configurations](../ultimate/multisid.md#owner-configurations-and-settings)

For an explicit SID entry, `pan` takes `Center`, `Left 1` through `Left 5`, or `Right 1` through `Right 5`. All four parts of an UltiSID share its hardware mixer pan. The score can omit pan or repeat the same value across those parts. Conflicting values are refused. For `cpu: turbo`, the server snapshots the turbo settings store and selects the registers mode advertised by firmware. Without `configure`, the playback result lists the needed device settings. [Ultimate turbo registers](../ultimate/hardware.md)

VICE playback automatically sets and restores `SidStereo` and `Sid2AddressStart` through `Sid8AddressStart` using the Binary Monitor. These are the resources for the VICE 3.10 options `-sidextra` and `-sid2address` through `-sid8address`. VICE requires a primary SID at `$D400` and supports up to eight SIDs. Ultimate mixer pan and turbo settings apply to Ultimate hardware.

## Advanced techniques (1.2)

### Echo and unison

Declare a destination voice with `echo: { voice: 1, delay: 6, volume: 0.4, detune: -7 }` or `unison: { voice: 1, detune: 8 }`. The destination takes its notes and instruments from the named source voice. Put the source in the timeline. The copy follows that source automatically.

- Echo shifts note onsets and releases by `delay` player calls and scales sustain by `volume` (0–1). The initial attack still uses the source attack and decay. Echoes that run beyond the end of the song are clipped. Place the echo on another SID and pan it separately on the mixer to spread it in stereo.
- Unison starts on the same call on another SID. Detune is in cents (±100), defaults to +5 for unison and 0 for echo, and also applies to arpeggios, wavetable pitch changes and glides. Doubling an oscillator at the same pitch does not produce a predictable increase in level. To tune a separately scored voice, give it `detune` in cents (±100). Two independently programmed oscillators can be detuned on the same SID. [Ultimate multi-SID measurements](../ultimate/multisid.md)

### Chord arpeggios and pitch bends

A groove entry `Cm7@arp` becomes a looping wavetable on one oscillator. It starts from the chord root in octave 3, then cycles through the chord tones once per player call. Use `{ chord: Cm7, arp: "0,3,7,10", speed: 2 }` to set the semitone offsets and calls per tone. The expanded loop takes the place of an instrument's wavetable for that entry. Layer transposition also shifts these notes.

Use `{ note: C4, bend: { to: G4, frames: 6 } }` to start at C4 and reach G4 in six calls, or use `to: -3` for a target three semitones below C4. `{ note: C4, slide_from: A3, portamento: 4 }` starts below C4 and rises over four calls, including on the first note of a song. Without `portamento` a scoop uses the instrument or pattern slide speed if set, otherwise four calls. Pitch moves linearly in SID frequency units. Use a wavetable without pitch changes for bends and scoops.

### Gate timing and oscillator reset

An instrument can set `hard_restart: { frames: 3, adsr: [0, 0, 0, 1], test: true }`. Before the next attack, the player clears GATE for the requested calls, loads the restart ADSR, and optionally holds the oscillator TEST bit. The next attack writes the note's ADSR and clears the restart TEST bit. The default is a two-call restart with zero ADSR. `frames: 0` keeps the regular ADSR and releases GATE before the next attack. `gate_off: 4` on a groove note releases it four calls before its written end, or earlier if the next attack needs a restart. Adjacent legato notes keep the gate on. [SID control register](sid-spec.md)

### CIA2 volume digis

Use standalone PRG output. Each sample entry names one SID and a list of zero-based player calls when it starts. All sample entries share the timer rate of 16–8,000 Hz. A later trigger on the same SID replaces the current sample. Separate SIDs can play simultaneous samples. A digi-only score can declare `voices: []` and empty timeline layers.

```yaml
samples:
  rate: 4000
  voices:
    - { sid: sid1, at: [0, 50], kit: kick }
    - { sid: sid1, at: [25, 75], kit: snare }
    - { sid: sid1, at: [88], hex: "8aef c987" }
```

The built-in kit synthesizes original `kick`, `snare` and `clap` hits. For inline data each hex digit is one unsigned 4-bit sample. `base64` packs two samples per decoded byte, high nibble first. The player expands them to one byte per sample in C64 memory and counts them against the `$D000` limit.

CIA2 timer A drives the NMI. It replaces the low nibble of `$D418` (or the equivalent register on the chosen SID), preserving filter mode in the upper nibble. It restores the current master volume on the next timer tick after the sample ends. The timer pauses when all sample SIDs are idle. All oscillators on that SID share that changing volume. A dedicated SID avoids modulating the volume of pitched voices. For Ultimate hardware set **Digis Level** in **UltiSID Configuration** to a suitable non-Off value (default Medium). [Ultimate multi-SID settings](../ultimate/multisid.md)

One active sample SID typically uses about 90 CPU cycles per timer tick including interrupt entry and exit, or about 720,000 cycles per second at 8 kHz. More sample SIDs increase the cost. The compiler budgets those interrupts alongside the score IRQ and reports when turbo is needed. Turn off any program that uses CIA2 timer A (including KERNAL RS-232) before starting the PRG. The timer and RAM NMI vector belong to the player during playback. [CIA2 timer and interrupt registers](../io/cia-spec.md)

### Additional library instruments

| Instrument | Technique |
|---|---|
| `lib:tom` | Noise transient followed by descending triangle pitches |
| `lib:clap` | Staggered noise bursts with alternating gate |
| `lib:open_hat` | Stepped high noise with an open tail |
| `lib:crash` | Longer falling noise decay |
| `lib:octave_bass` | Sawtooth alternating between the note and its octave |
| `lib:wide_pwm_pad` | Slow attack and a wide looping pulse sweep |
| `lib:pluck_arp` | Short pulse and triangle arpeggio |
| `lib:noise_lead_attack` | One call of noise before a pitched sawtooth lead |

### Not supported

Time signatures other than 3/4 and 4/4, per-note velocity, multiple subtunes, sample data loaded from external files, and arbitrary memory/register writes. Instrument recipes are starting points rather than emulations of any commercial player or specific SID model.
